1 · Built & live (MVP) DONE

Hospital

  • 10-second request form (group, component, units, urgency, needed-by, ward)
  • Ranked results + map: ETA, stock, expiry badge, data freshness, exact vs compatible (clinician flag), "why this rank"
  • One-tap reserve; live tracker Requested → Confirmed → Reserved → Picked up → Delivered
  • Split reservation: "Cover all N units across K banks" — one tap reserves across several banks
  • Auto-reroute to next-best bank if no confirmation in 90 s; holds return to stock after 45 min
  • Own-stock tab with "Offer for transfer"; critical "alert everyone" (rate-limited); duplicate-request detection

Blood bank

  • Stock grid by group × component: on hand, reserved, expiring 48 h / 7 d, shortage/surplus colours
  • Live request queue: Confirm / Partially confirm / Decline with reason; critical on top; auto-reroute countdown
  • Add / use / remove units; camera barcode & QR scan (open-source ZXing); printable unit QR labels
  • Connected systems card: e-RaktKosh (public portal, hourly auto-sync), RAKT blood-bank software connector, eBloodConnect (partner access)
  • Transfer suggestions: approve / modify qty / dismiss / mark received
  • Donor drive with eligibility funnel before sending; incoming donors with confirmation codes

Donor (phone view)

  • QR quick-join, three separate consent toggles, eligibility countdown, honest impact count
  • Full-screen alert (no patient identity) → "I can come" reveals address, time window, 6-digit code
  • Hindi / Marathi alerts translated by an open model (Workers AI)
  • Quiet hours, weekly alert cap, opt-out / opt back in
  • Shareable donation certificate (Share / WhatsApp / Save), "eligible again" calendar reminder, pre-visit checklist

Doomsday command & trust layer

  • Surge mode (flood at Kurla, mass-casualty at Dadar — real flood-prone sites); per-group stock-out countdowns
  • Expiry-aware transfer planner; before/after outcome meter (24 h shortfall, expiring units, sites at risk)
  • 3D base map (extruded buildings, relief, tilt/rotate) with risk-coloured site dots and animated transfer arcs
  • AI situation brief (open model on Workers AI, template fallback)
  • Hash-chained, tamper-evident audit ledger of every action
  • Real-time sync of every screen (Durable Object WebSockets)

Beyond the PRD

  • MCP server (15 tools): ChatGPT / Claude can query the live city and — only after the user confirms — reserve blood, start a surge, approve transfers, send drives. Every AI action is logged as ai:<client>. Verified end-to-end with a real Claude client.
  • WhatsApp bot (open-wa gateway on a laptop): Hinglish blood requests ("Sion mein 2 O negative platelets chahiye") → top 3 real banks; JOIN signup; YES → confirmation code; STOP opt-out; privacy filter ignores personal chats.
  • Official WhatsApp Business Cloud API channel built into the Worker (webhook, templates, click-to-chat onboarding) — awaiting Meta credentials.
  • SMS channel via the open-source SMS Gateway for Android app.
  • RAKT connector (blood bank management software): built to RAKT's published OpenAPI schema — pulls per-bag stock with collection dates, so a RAKT bank's units get real expiry dates (e-RaktKosh only gives counts). Idempotent sync; 5 tests on schema-shaped fixtures; RAKT's live server confirms our auth header format ("Invalid API key" with a test key).

Data: real vs simulated

Real (open data)25 Mumbai blood banks + 6 municipal hospitals (data.gov.in + OpenStreetMap); stock counts by group × component and each bank's last-update time (e-RaktKosh snapshot, 9,761 units); shelf lives (Drugs Rules G.S.R. 166(E) 2020); blood-group shares and collection volumes (cited)
ModelledPer-bag expiry dates (e-RaktKosh publishes counts only), daily demand, surge multipliers (cited assumptions)
SyntheticEvery donor, patient and request (privacy)

  • Quality: TypeScript strict, Zod-validated API shared by server and client, 130 unit tests, end-to-end smoke test (scripts/smoke.mjs)
